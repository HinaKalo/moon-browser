# 插件体系与开发规范

Moon Browser 以 Lua 作为浏览器定制的主要语言，并为系统集成保留独立的 Windows EXE 插件。用户脚本是 Lua 运行时的第一个内置扩展。浏览器内核继续负责窗口、WebKit、标签内存调度和权限判定。

## 选择运行时

| | Lua 定制插件 | 原生 EXE 系统插件 |
| --- | --- | --- |
| 适合 | 网页定制、快捷命令、工作流、界面布局和偏好配置 | 系统服务、设备、原生库、计算密集型任务 |
| 执行方式 | 浏览器内嵌的 Lua VM。由宿主提供有界的 `moon` API | 独立进程执行原生代码。通过 stdin/stdout 调用宿主 |
| 权限边界 | 运行环境和宿主能力校验 | 浏览器能力需要授权。进程按当前 Windows 用户权限运行 |
| 首版入口 | [Lua 用户脚本](./lua-userscripts) | [EXE 预览协议](./protocol-v1) |

内置与可选插件由相同的运行时、权限判定和开发工具处理。内置默认启用项由浏览器发行包登记。可选项由用户选择安装。页面访问权限按网站和插件独立授予。

## 包与兼容性

下一版普通插件包以 `plugin.json` 声明 `id`、`version`、`apiVersion`、`runtime`、`entry`、`contributes`、`permissions` 和 `events`。`runtime` 取 `lua` 或 `native`。入口路径必须留在包目录内。每个插件 ID 由发布者名称和插件名组成，包版本采用语义化版本。

| 字段 | 用途 |
| --- | --- |
| `id` | 作为安装、授权、存储和升级的键，跨版本稳定。 |
| `version` | 插件自己的发布版本。 |
| `apiVersion` | 宿主 API 主版本。新增兼容字段和方法无需提升主版本。 |
| `runtime` | 选择 Lua VM 或原生进程。 |
| `entry` | 包内主文件，例如 `main.lua` 或 `Plugin.exe`。 |
| `contributes` | 声明菜单命令、设置项和允许扩展的界面位置。 |
| `permissions`、`events` | 声明需要的能力和感兴趣的宿主通知。 |

当前 Lua 用户脚本采用单文件元数据格式，当前 EXE 插件继续使用 `api_version: 1` 格式。宿主按已声明的协议版本处理历史包，共用包规范将在统一 API 实装时发布。旧权限只延续到同一插件标识和同等权限范围。

## 统一 API

- 一个能力一个命名空间。菜单和快捷键由 `moon.commands` 管理，标签由 `moon.tabs` 管理，持久化由 `moon.storage` 管理。UI 声明使用 `moon.ui`，网页操作留在 `moon.dom`。
- 同名 API 的字段、错误和授权含义一致。Lua 通过函数调用和事件处理器使用能力。EXE 通过 JSON-RPC 请求和通知使用能力，原生进程可以批量请求减少 IPC 开销。
- 权限声明携带作用域。标签标题与 URL、网站 DOM、下载和系统集成各有边界。宿主按实际请求校验，撤销后停止分发敏感事件。平台适配保持业务 API 语义稳定。
- 宿主从稳定的错误码生成面向用户的提示。SDK 提供类型、参数检查和开发日志。高频事件可合并，长任务可取消，有状态的操作使用显式提交。

## 生命周期与性能

Lua 插件按需启动。用户脚本按文档实例运行，运行结束回收 VM。需要跨事件状态的 Lua 插件通过有配额的宿主存储保存数据。扩展命令运行在受控调度器上，不能无限占用 UI 线程。

原生插件采用独立进程模型。低频命令可以按需启动。后续常驻模式面向低延迟系统服务，先握手协商能力，再以异步请求处理工作，接受就绪、超时、退出和崩溃监控。宿主为队列、内存与请求持续时间设置预算。

下载、标签回收和渲染器重建由宿主管理。插件使用可失效的标签句柄，支持在网页恢复或浏览器重启后重新读取状态。窗口绘制和滚动等高频路径留在宿主，Lua 提供布局与行为配置。

## 开发、测试和发布

1. 根据能力选择运行时，先写最小清单和示例。从 [Lua 快速开始](./lua-userscripts)或 [EXE 快速开始](./guide)运行第一个端到端流程。
2. 明确权限和回退。测试正向与拒绝路径、关闭或卸载后的行为、超时和进程崩溃。网页脚本还要测试跨站跳转、排除规则和子框架。
3. 发布包应记录最低宿主 API、版本变更、权限变动和可复现构建方式。正式 SDK 将公开清单 Schema、Lua 参考、原生协议、样例和兼容性测试。
4. Moon 插件市场负责发布者身份、签名、来源追踪与更新元数据。市场沿用相同包格式。新增权限须获批准，异常版本可撤回，浏览器可回滚到上一个已认可版本。

## Lua 定制的开放顺序

1. **网页定制。** Lua 用户脚本、网址范围确认、受控 DOM 操作和逐项启停已实现。
2. **浏览器工作流。** 接入命令、标签查询、快捷键、设置和私有存储。统一接口见 [API 草案](./api)。
3. **浏览器界面。** 用 Lua 描述工具栏、侧栏、菜单和新标签页的贡献。宿主管理交互反馈、可访问性、DPI 与输入法。
4. **系统级能力。** 保留原生 EXE 实现高吞吐和 Windows 集成，并允许获授权的 Lua 工作流调用其公开能力。
